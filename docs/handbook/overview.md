# 这个知识库能帮你做什么？

**它把 FTC 队伍的编程要求、工具教程和使用经验整理在一起，让队员能查资料，也让 AI 写代码时有具体要求可参考。**

例如，你让 AI 修改自动程序时，希望它沿用队伍的硬件命名、参考正确的工具用法，并在修改后检查有没有违反已收录的要求。这个项目就是为这些事情准备的。

这里的 **Agent** 指能读取项目文件、运行命令和修改代码的 AI 编程工具。你不需要先弄懂这个词，也可以直接阅读网站上的教程。

## 已经可以做的事情

### 2. 把队伍要求交给你正在使用的 AI

你可以把知识库接入现有 FTC 项目。安装工具会记录队号、赛季和使用的知识库版本，并放入供 AI 阅读的操作说明。这份操作说明叫 **Skill**。

以后让 AI 改代码时，它可以先读取适用于这个项目的要求，再动手修改。你仍然使用原来的 AI 编程工具。

不同 AI 工具对 Skill 的支持不同。如果它没有自动读取，你需要明确让它按项目里的说明操作。

### 3. 找出当前队伍应该遵守哪些规则

知识库里可能同时有官方要求、某个队伍的约定和跨队共享经验。工具会根据**队号和赛季**选出已批准且适用的规则；如果要求之间存在无法解决的冲突，会报出来。

这一步叫 `resolve`，可以理解为：**“先给我这次该看的规则清单。”**

例如，20827 的队伍约定不应被默认当成另一支队伍的约定。也不能因为某个参数曾在旧机器人上使用过，就认为它适合今年的机器人。

### 4. 检查这次代码修改有没有违反规则

AI 修改完成后，可以调用检查工具，查看**本次改了哪些文件、增加了哪些代码**。这份修改对比通常叫 **diff**；检查命令叫 `check`。

能用明确条件判断的问题，会列为违规；需要人判断的事项，会列为提醒。例如，某条已启用规则禁止修改指定路径，那么触及那个路径的改动就会被报告。

**检查通过只表示没有发现它能检查出的违规。** 它不能保证代码没有其他错误，也不能证明机器人会按预期运动。当前一些规则也可能误报，见[已知限制](/reference/checks/)。

### 5. 让队员共用同一版知识库

项目接入时会记住一个确定的知识库版本，避免你和队友在同一个项目里使用不同要求。新队员拿到项目后，可以恢复这一版本并检查安装是否完整。

需要更新时，再明确选择新版本。相关步骤见[团队协作与升级](/agent/upgrades/)。

### 6. 在本地向 AI 提问，也可以让它修改代码

项目自带一个聊天工具，可以结合本地项目与知识资料回答问题。

- **Ask（问答）**：用于解释代码和规则，默认不改文件。
- **Edit（编辑）**：允许它修改代码；你可以查看修改对比、撤销最近一次修改，或放弃它在本次会话中的改动。

这部分需要配置模型服务。回答会区分规则依据、从代码中看到的情况和推测，但仍需要你检查结果。

### 7. 用本地网页或 Android Studio 插件操作

如果不习惯在终端输入命令，可以使用[本地网页界面](/guides/local-web/)，或查看 [Android Studio 插件指南](/guides/android-studio/)。

**你现在访问的网站是说明书。** 它本身不会读取电脑上的项目，也不能直接替你改代码；聊天和编辑功能需要在你自己的电脑上运行。

### 8. 从项目经验中提出新规则，再交给负责人审核

工具可以分析代码并提出可能值得保留的经验。这些建议先是**候选规则**，意思是“有人提出了，还没正式采用”。负责人检查内容、来源和适用范围后，可以批准或驳回。

AI 提出的建议不会自动成为正式要求。规则里可以保留来源和审批信息，方便队员理解“为什么这样写”。

### 9. 检查知识文件和项目安装是否正确

- `validate`：检查知识文件的格式和必要信息是否符合要求，例如批准的规则是否包含审批记录。
- `verify`：检查知识库是否正确接入项目，并报告当前代码检查的结果。

这能帮助区分“工具没装好”和“工具装好了，但代码有问题”。检查文件格式也不等于证明规则内容一定正确。

### 10. 把代码检查接到团队的提交检查中

维护者可以配置 GitHub 等平台，让提交的代码自动运行规则检查。这类自动检查通常叫 **CI**。

项目提供相关说明，但安装知识库不会自动完成 CI 和合并限制的配置。需要负责人按[CI 指南](/reference/ci/)设置。

## 一次实际使用大概是什么样？

假设你想让 AI 修改自动程序中的一个步骤：

1. **先接入项目。** 填明自己的队号和赛季，确认知识库安装成功。
2. **告诉 AI 要改什么。** 例如“修改等待舵机的步骤，并遵循项目知识库”。
3. **AI 先取规则，再改代码。** 它应说明参考了哪些要求。
4. **检查修改结果。** 运行代码检查，查看违规和需要人工确认的提醒。
5. **自己验证程序。** 阅读修改对比，完成必要的编译与真机测试。

完整步骤见 [Agent 接入流程](/agent/workflow/)。

## 哪些事情还不能做？

- 还不能通过自带聊天工具自动完成“运行构建 → 读错误 → 修复”的 Run 模式。
- 还没有官方文档实时联网检索功能。
- 还不能自动把程序部署到 Control Hub。
- 还没有专门的网页审批管理界面和不可变审批历史。
- 不能代替队员决定机器人整体方案，也不能保证 AI 的回答或机器人的实际行为正确。

已实现能力和测试范围的详细记录见[版本与验证范围](/reference/status/)。

## 需要付费或准备 API key 吗？

**看网站教程不需要。** 本地选规则、检查代码和检查安装也不调用模型，不需要额外模型 key。

你正在使用的 AI 编程工具是否收费，由它的供应商决定。使用本项目自带的 AI 聊天、编辑或模型提取功能，需要配置模型服务，可能产生对应的 API 费用。

第一次使用，建议先看[快速开始](/getting-started/)。只想学习 FTC 工具，可以直接选择上面的教程。
